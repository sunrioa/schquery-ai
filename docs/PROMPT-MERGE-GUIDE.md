## 🎯 问题背景

在配置 AI 对话时，存在三个提示词来源：

1. **用户提示词**：在 ChatPreset 中配置的 `systemMessage`，定义 AI 角色和行为规则
2. **知识库提示词**：在 KnowledgeInfo 中配置的 `systemPrompt`，定义如何使用知识库
3. **MCP 网络检索内容**：从网络获取的实时信息

### 原有问题

- **合并模式（merge）下**：知识库提示词会覆盖用户提示词，导致用户精心设计的 AI 角色失效
- **降级模式（fallback）下**：知识库和 MCP 内容堆叠，缺少优先级控制
- **无法调整权重**：无法控制哪个来源的内容更重要

---

## 💡 解决方案

### 核心思想

1. **延迟注入**：`KnowledgeRagAdvisor` 不再立即注入内容，而是保存到 context
2. **统一融合**：`McpRagAdvisor` 负责统一融合所有提示词
3. **策略可配**：通过 `PromptMergeStrategy` 提供 4 种融合模式
4. **权重控制**：每个来源有独立的权重配置

### 技术架构

```
用户消息
  ↓
SensitiveFilterAdvisor (过滤敏感词)
  ↓
IntentRecognizerAdvisor (识别意图)
  ↓
KnowledgeRagAdvisor (检索知识库 → 保存到 context)
  ↓
McpRagAdvisor (检索 MCP → 统一融合 → 注入 system message)
  ↓
AI 模型
```

## 📚 融合模式详解

### 1. USER_FIRST（用户优先）⭐ 推荐

**结构**：
```
## 角色定位与核心任务
[用户在 ChatPreset 中定义的 systemMessage]

## 参考资料（知识库）
以下内容来自知识库检索，请在遵循上述角色定位的前提下参考使用：
[知识库提示词]
[知识库检索内容]

## 补充资料（网络检索）
以下内容来自网络检索，仅作辅助参考：
[MCP 检索内容]

## 回答要求
- 严格遵守【角色定位与核心任务】中定义的角色和规则
- 优先使用【参考资料】中的知识，但表达方式应符合角色定位
- 如果参考资料不足以回答，可以使用通用知识，但需说明
```

**适用场景**：
- ✅ 客服机器人：用户定义的服务规则最重要
- ✅ 定制化助手：需要特定的回答风格和规则
- ✅ 教育助手：知识库提供内容，但教学方式由用户定义

**示例**：
```java
// ChatPreset.systemMessage
"你是一个专业的医疗健康顾问。你的回答应该：
1. 通俗易懂，避免使用专业术语
2. 强调及时就医的重要性
3. 不提供具体的诊断和治疗建议"

// 知识库内容
"心肌梗死的症状包括：胸痛、呼吸困难..."

// 最终效果
"根据您描述的症状，可能与心血管问题有关。常见症状包括胸痛和呼吸困难。
但请注意，我无法提供具体诊断，强烈建议您尽快前往医院进行专业检查。"
```

### 2. KNOWLEDGE_FIRST（知识库优先）

**结构**：
```
## 核心指引（知识库）
[知识库提示词]

## 知识库检索内容
[知识库内容]

## 补充要求
[用户提示词]

## 回答策略
- 严格基于【知识库检索内容】回答
- 在满足知识库要求的基础上，兼顾【补充要求】
```

**适用场景**：
- ✅ 专业问答：法律、医疗等必须基于权威知识库
- ✅ 合规场景：不允许 AI 自由发挥
- ✅ 考试辅导：答案必须来自教材知识库

**示例**：
```java
// KnowledgeInfo.systemPrompt
"严格基于医疗知识库回答，不得添加任何未经验证的信息。"

// 知识库内容
"根据《临床医学指南》，心肌梗死的标准诊断..."

// 用户提示词（仅作微调）
"请用通俗语言解释"

// 最终效果
"根据权威医学指南，心肌梗死的诊断需要满足以下标准..."
（严格基于知识库，但表达更通俗）
```

### 3. BALANCED（平衡模式）

**结构**：
```
### 用户角色定位 (权重: 60%)
[用户提示词 - 按权重分配篇幅]

### 知识库提示 (权重: 25%)
[知识库提示词和内容 - 按权重分配篇幅]

### 网络检索内容 (权重: 15%)
[MCP 内容 - 按权重分配篇幅]
```

**适用场景**：
- ✅ 实验和调优：需要测试不同权重配置
- ✅ 综合场景：各信息源同等重要
- ✅ 灵活应用：根据具体需求动态调整

---

### 4. LAYERED（分层模式）

**结构**：
```
# AI助手配置（多层提示词融合）

---
## 用户角色定位
**[核心层级]**
[用户提示词]

---
## 知识库提示
[知识库提示词]

---
## 知识库内容
[知识库检索内容]

---
## 网络检索内容
[MCP 内容]

---
## 融合规则
- 所有层级的提示词都需要遵守
- 当出现冲突时，核心层级优先
- 各层级内容应相互补充，而非相互替代
```

**适用场景**：
- ✅ 调试分析：清晰看到各层级提示词
- ✅ 复杂场景：需要精确控制各层级
- ✅ 教学演示：展示提示词工程

## ⚙️ 配置方法

### 方法一：系统全局配置（推荐）

1. 执行 SQL 脚本：
```bash
mysql -u root -p your_database < docs/prompt-merge-strategy-config.sql
```

2. 在管理后台修改配置：
   - 路径：`系统管理` → `参数设置`
   - 配置项：
     - `chat.default.promptMergeMode`：设置为 `user_first` / `knowledge_first` / `balanced` / `layered`
     - `chat.default.mcpMode`：设置为 `off` / `fallback` / `merge`

### 方法二：直接修改数据库

```sql
-- 设置融合模式为"用户优先"
UPDATE sys_config
SET config_value = 'user_first'
WHERE config_key = 'chat.default.promptMergeMode';

-- 设置 MCP 模式为"降级"
UPDATE sys_config
SET config_value = 'fallback'
WHERE config_key = 'chat.default.mcpMode';
```

### 方法三：未来扩展（需要修改数据库结构）

在 `chat_preset` 表中为每个预设单独配置：

```sql
ALTER TABLE chat_preset
ADD COLUMN prompt_merge_mode VARCHAR(50)
COMMENT '提示词融合模式：user_first/knowledge_first/balanced/layered';
```

## 🎬 使用场景

### 场景1：智能客服机器人

**需求**：
- 用户定义了详细的客服规则（礼貌用语、处理流程等）
- 知识库包含产品FAQ和解决方案
- 偶尔需要搜索最新的产品信息

**配置**：
```
promptMergeMode: user_first
mcpMode: fallback
```

**效果**：
```
用户提示词（核心）：
"你是XX公司的客服代表。回答时需要：
1. 使用礼貌用语，称呼用户为'您'
2. 先倾听问题，再提供解决方案
3. 如果无法解决，引导用户联系人工客服"

知识库内容（参考）：
"产品A的退货流程：1. 联系客服... 2. 填写退货单..."

最终回答：
"您好！关于产品A的退货，我来为您详细说明：
首先，您需要联系我们的客服团队...
[遵循用户定义的服务规则，使用知识库的具体信息]"
```

---

### 场景2：法律咨询系统

**需求**：
- 必须严格基于法律知识库回答
- 不允许 AI 自由发挥或猜测
- 用户提示词仅用于调整表达方式

**配置**：
```
promptMergeMode: knowledge_first
mcpMode: off
```

**效果**：
```
知识库提示词（核心）：
"严格基于《民法典》等法律文本回答，不得添加任何未经验证的信息"

知识库内容：
"根据《民法典》第XX条，合同的成立需要..."

用户提示词（微调）：
"请用通俗语言解释"

最终回答：
"根据法律规定，合同的成立需要满足以下条件...
[严格基于知识库，但表达更通俗]"
```

---

### 场景3：通用AI助手

**需求**：
- 综合多方信息
- 灵活应对各种问题
- 知识库、网络、通用知识都可能用到

**配置**：
```
promptMergeMode: balanced
mcpMode: merge
权重配置：
  user: 0.5
  knowledge: 0.3
  mcp: 0.2
```

### 3. 常见问题排查

**问题1：用户提示词没生效**
- 检查融合模式是否为 `knowledge_first`
- 改为 `user_first` 模式

**问题2：知识库内容被忽略**
- 检查知识库是否检索到内容（`knowledgeHit` 标志）
- 确认融合模式不是 `knowledge_first` 但知识库为空

**问题3：MCP 内容过多干扰回答**
- 将 `mcpMode` 从 `merge` 改为 `fallback`
- 或降低 MCP 权重（`chat.weight.mcp`）
